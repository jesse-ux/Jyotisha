# Antigravity AI 下一步产品修复方案 (Round 9)

## 1. 对标
虽然我们在后台做了世界上最严谨的黑盒证据检验，但在产品前台展示上，相较于 VedAstro 极其坦诚的开放接口集，我们的 Web/App 在“自我能力边界”的披露上存在严重断层。普通用户极可能对尚未充分校验绝对值的大运（Dasha）和六维力量（Shadbala）深信不疑。

## 2. 开源参考
针对如何向用户传达“这部分仍在参考外部标杆计算”的态度，我们需要在界面和问答交互中引入安全区概念。不同于 JHora 完全不解释而是甩给用户满屏选项，我们需要化繁为简，在用户查阅特定指标时进行友好的提示。

## 3. Bug
我们强烈建议 Codex 按照以下优先级序列，立刻开始执行普通用户产品路径的填坑与透明度重构：

- **第一步（最迫切）：Web/App 侧暴露 Trust Center**
  在 `jyotish-app/index.html` 与 `main.js` 的视图层，尤其是大运与力量面板附近，增设“数据可信度”或“Dasha/Shadbala Calibration Status”微标与说明弹窗。明白无误地写明：“该部分的绝对起步时间与强度值正通过外部真实靶心（如 JHora 等）进行严密收集校验，当前状态为参考标定中。”
- **第二步：动态读取校准大盘**
  修改 `jyotish_api_server.py`，新增诸如 `/api/capability_audit` 的节点，或者直接在前端打包时把 `oracle queue summary` 的 `ready_for_calibration` 数量进行静态展示，让用户亲眼看到数字从 0 变 5 的演进过程。
- **第三步：AI 与 Skill 文案同步封印**
  在 `jyotish-app/ai-chat.js` 以及 `SKILL.md` 的系统提示词中，增加硬性规定：当用户提问关于特定日期的具体人生起步大运时，强制 AI 必须首先声明当前模型的外部证据验证状态，不可满口打包票。
- **第四步：一键打包交付用户**
  通过 Pake 或 Docker Compose 一键脚本，把目前的 Web 端与后端 API 融合成一个“双击即可使用”的桌面程序或镜像，彻底解决让小白去配置 NPM 和虚拟环境的千古难题。
