# Antigravity AI Prompt Pack 解盘可信度审计 (Round 24)

| 审计维度 | 状态判定 | 说明 |
|---|---|---|
| 1. 引用计算证据 | 🟡 偏弱 | 当前 Prompt 会塞给 LLM 整个星盘 JSON，但没强制它说出原因。 |
| 2. 标注不确定性 | 🔴 无 | 未在 Prompt 中显式要求 LLM 加上“该推测具有不确定性”。 |
| 3. 避免过度预测 | 🟡 偏弱 | LLM 经常喜欢算命说“你会在明年发财”，我们未加阻止指令。 |
| 4. 解释 Dasha | 🟢 可 | JSON 包含了运势时段，LLM 懂。 |
| 5. 解释 Shadbala | 🟢 可 | JSON 包含了七星强弱排行，LLM 会解读最高星。 |
| 6. 解释 Yoga | 🟢 极佳 | 内部 Yoga 引擎给了极详细的 name 和 description。 |
| 7. 缺外部 Oracle | 🟡 中等 | 给了 `oracle_progresses` 数组，但并未硬编码要求大模型用免责声明警告用户。 |
| 8. 可验证结论 | 🔴 无 | LLM 不会反问用户“这些历史年份是不是发生过大事”。 |
| 9. 中文体验 | 🟢 极佳 | 强制了使用中文和通俗印度占星术语。 |
| 10. 隐私 | 🟢 极佳 | 在拷贝前抹除了名字。 |
| 11. LLM 幻觉对抗 | 🔴 弱 | 没让 LLM 对矛盾的征象（比如同时存在大吉和大凶瑜伽）做辩证分析。 |
| 12. 系统设定 (Persona) | 🟡 中等 | 应该设定为“一位严谨的吠陀占星数据解析员”而不是占卜师。 |
| 13. Token 成本 | 🟡 偏高 | 全塞进去容易突破 8K token。 |
| 14. 应对不同模型 | 🟡 中等 | Claude/GPT4 会表现很好，但本地小模型会乱语。 |
| 15. D9 落座关联 | 🔴 弱 | Prompt 没特别强调 D1 和 D9 结合看的重要性。 |
| 16. 下一步建议 | 优先 | 重写前端拷贝的 System Prompt 前缀，加强防幻觉护栏。 |

**副手下一轮任务**：设计一个“对抗 LLM 星盘幻觉”的三段式 System Prompt。
**Codex 可做任务**：在生成 Prompt 时加上这句：“你必须明确说明你的所有预测尚未经过人类大规模校准验证，不构成生活决策依据”。
