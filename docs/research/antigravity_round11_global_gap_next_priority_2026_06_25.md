# Antigravity AI 全球对标差距与下一优先级 (Round 11)

## 重新透视：距离普通用户成品的最高优先级缺口

我们不再以“比拼计算接口数量的极客炫技”为坐标，而是转为“让普通中文用户能看懂、信得过、用得上”的产品化视角进行重新排布。

| 优先级 | 缺口 | 为什么影响普通用户 | Codex 下一步建议 |
|---|---|---|---|
| **#1** | **缺乏开箱即用的交付壳子**<br/>(对比 JHora / Hora Prakash) | 普通用户不会使用 `npm run build` 和 `python3 api_server.py`，如果没有双击运行的桌面端或线上直连环境，我们做再多校验也是孤芳自赏。 | 筹划 Pake/Tauri 构建：一键打包前端网页与本地轻量级 Python 核心，降低用户的首次使用摩擦。 |
| **#2** | **报告无法离线带走校准底色**<br/>(对比 本项目 AI Native 体验) | 用户关掉网页，或者把排盘报告另存分享给占星师时，界面上的 Trust Center 就丢失了。对方会误以为这是一个纯粹硬核的确定盘。 | 补修导出模块：将 `DASHA_SHADBALA_CALIBRATION_STATUS` 强行嵌入打印的 PDF / 导出的 HTML 星盘底层。 |
| **#3** | **无处投递外部真值**<br/>(对比 JHora 绝对基准池) | 后台的 `0/5` 队列在纯代码里是个冰冷的 JSON，普通占星专家即使想帮你提供 JHora 截图验证，也无从下手（看不懂 JSON Schema）。 | 构建可视化打榜前端：把 `oracle_collection_queue` 的采集任务，做成一张傻瓜式 Web 表格（填空并传截图）。 |
| **#4** | **API 方法极其贫瘠**<br/>(对比 VedAstro 596+ 方法) | 当开发者试图把我们接到其他自动化流水线上时，会发现我们除了一套打捆好的长串推断外，缺少大量基础单体指标调用（例如单查木星过境某度数的 API）。 | 在完成核心力量体系标定后，逐步铺设微粒度的基础占星推算 API。 |
