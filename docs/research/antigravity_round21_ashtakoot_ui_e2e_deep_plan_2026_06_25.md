# Antigravity AI Ashtakoot UI/E2E 深度测试设计 (Round 21)

我们设计了极度繁琐的 20 条测试矩阵，以保障 Ashtakoot 用户流程的万无一失：

1. **完整出生资料**：男女完整表单提交，验证 API 是否成功。
2. **只输月亮黄经**：最核心的快算机制，必须瞬间在前端算出 36 分结果。
3. **API 宕机兜底**：断网状态点击计算，验证能否算出正确结果。
4. **深度分析 API**：连网点击，检查是否渲染 D9 同步信息。
5. **总分显示**：断言 DOM 存在 `36 / 36` 的满分组合（使用同坐标月亮）。
6. **分项显示**：检查 Varna/Vashya 等 8 项的 8 行 div 是否存在。
7. **火星煞（Kuja Dosha）**：检查是否渲染了火星交角警告。
8. **D9 专题**：确认出现了 `Navamsa` 相关的解读字眼。
9. **Dasha 同步**：检查是否有大运同步评价。
10. **保存样本**：点击保存，检查 LocalStorage。
11. **导出报告**：点击导出，确保 PDF Blob 被构建。
12. **AI Prompt 联动**：复制 Prompt 时，检查是否有男女月亮位置。
13. **移动端适配**：缩小为 iPhone X 尺寸，确保表格没有横向溢出。
14. **空输入报错**：留空计算，检查必须抛错 `缺少月亮数据`。
15. **非法经度报错**：输入 400 度，抛出 `0-360 之间` 警告。
16. **时区畸形报错**：输入无效时区。
17. **边界值测试**：输入 0 和 360，验证其循环算法等效性。
18. **防呆测试**：男女资料完全一样时，给出一个“自恋”警告或确认窗。
19. **隐私提示**：合盘资料不在云端保留的免责声明。
20. **Oracle 进度**：顶端悬浮窗提示当前合婚算法未经过 5 个 case 验证。

**最小 Codex 改动建议**：使用 Playwright 先把第 2、14、15 条完成。
